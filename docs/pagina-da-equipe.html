O que ela faz

Uma agenda que a equipe inteira escreve

A maioria das agendas de empresa tem um dono: alguém marca, os outros olham. Esta parte do princípio oposto — todo mundo edita tudo, e cada mudança fica registrada com nome e data. A conversa sobre o evento acontece no próprio evento, e não em cinco mensagens soltas.

Qualquer pessoa cria
Clique em um dia do calendário ou no botão + Novo evento.
Qualquer pessoa edita
Todo membro pode alterar qualquer evento, inclusive os criados por colegas.
Comentários no evento
Combine detalhes, avise atrasos, deixe a pauta. Cada um edita e apaga o próprio.
Histórico de alterações
Quem criou, quem editou, o que mudou e quem comentou — tudo datado.
Mês e lista
Calendário mensal colorido por pessoa, ou lista em ordem cronológica.
Busca
Procura por título, descrição ou local em toda a agenda.
Dia inteiro e vários dias
Para feriados, viagens e mutirões que não cabem em um horário.
Página da equipe
Lista de quem usa a agenda; administradores promovem colegas.
Acesso protegido
Login com senha e código de convite. Tema claro ou escuro conforme o aparelho.
Fuso de cada um
As datas trafegam em UTC e aparecem no horário local de quem está olhando.

Como começa

Três minutos até a primeira tela

Não há banco de dados para instalar: o arquivo SQLite é criado sozinho na primeira execução. A primeira pessoa que se cadastrar vira administradora.

Terminal 
git clone https://github.com/luizhenrique29619-rgb/AGENDA-COMPARTILHADA.git
cd AGENDA-COMPARTILHADA
npm install
cp .env.example .env      # ajuste a porta e o código de convite
npm start

Abra http://localhost:3000. Para ver a agenda já com conteúdo, rode npm run seed — ele cria três pessoas e alguns eventos, e o login de exemplo é ana@empresa.com com a senha senha1234.

Permissões

Quase tudo é de todos

Há só dois perfis: membro e administrador. A diferença entre eles é menor do que se espera, porque criar e editar é liberado para a equipe inteira.

O que cada perfil pode fazer
Ação Membro Administrador
Criar evento ✓ ✓
Editar qualquer evento
inclusive os criados por colegas		 ✓ ✓
Comentar ✓ ✓
Editar o próprio comentário ✓ ✓
Excluir evento só os que criou ✓
Excluir comentário só os próprios ✓
Promover ou rebaixar colegas ✕ ✓

A exclusão é o único ponto mais fechado: como não dá para desfazer, ela fica com quem criou o evento ou com um administrador. Se a sua equipe preferir liberar a exclusão para todo mundo, remova a checagem na rota DELETE /:id em src/routes/events.js.

Como alguém entra

Convidando a equipe

  1. Publique a agenda em um endereço que a equipe alcance.
  2. Defina um INVITE_CODE e mande para os colegas junto com o link.
  3. Cada pessoa clica em Criar conta e informa nome, e-mail de trabalho, senha e o código.
  4. Pronto: todos veem a mesma agenda, e as edições de um aparecem para os outros ao recarregar.

Quem entra primeiro vira administrador — então crie a sua conta antes de mandar o link. Sem o código de convite, ninguém consegue se cadastrar.

Hospedagem

Três caminhos para deixar no ar

O mesmo código roda nos três. O que muda é onde ficam os dados e quanto custa. Abra o caminho que fizer sentido para ver os comandos.

Render + Turso Grátis Nenhuma das duas contas pede cartão. Dorme após 15 min sem uso — o primeiro acesso depois disso leva cerca de um minuto.

Primeiro crie o banco em turso.tech e guarde a URL (libsql://…) e um token de acesso. Depois, no render.com: New → Blueprint, escolha este repositório e o Render lê o render.yaml sozinho, pedindo três variáveis.

Criando o banco pelo terminal 
curl -sSfL https://get.tur.so/install.sh | bash
turso auth signup
turso db create agenda
turso db show agenda --url        # a URL
turso db tokens create agenda     # o token

Hospedagem gratuita quase nunca tem disco que sobreviva a reinícios. É por isso que este caminho usa o Turso: com o banco na nuvem, os dados continuam lá mesmo quando o serviço dorme ou reinicia.

Fly.io Alguns dólares por mês Roda o Dockerfile do repositório, com disco próprio e servidor em São Paulo. Não dorme, mas pede cartão de crédito no cadastro.

O script deploy-fly.sh cria o app, o volume, gera o código de convite e publica. Pode ser executado de novo com segurança — cada etapa já concluída é ignorada. Ao final ele imprime o endereço e o código.

Terminal 
curl -L https://fly.io/install.sh | sh    # instala a CLI
fly auth login                            # abre o navegador
./deploy-fly.sh agenda-da-sua-equipe      # faz o resto
Ou comando a comando 
fly launch --no-deploy --copy-config --name SUA-AGENDA --region gru
fly volumes create agenda_dados --size 1 --region gru
fly secrets set INVITE_CODE="um-codigo-secreto-da-equipe"
fly deploy --remote-only
fly open
Servidor próprio ou VPS O que você já paga Qualquer máquina com Docker, inclusive um servidor da empresa. Em troca, o servidor fica por sua conta.
Subindo com Docker Compose 
git clone https://github.com/luizhenrique29619-rgb/AGENDA-COMPARTILHADA.git
cd AGENDA-COMPARTILHADA
INVITE_CODE="um-codigo-secreto-da-equipe" docker compose up -d

A agenda responde na porta 3000 e o banco fica no volume agenda-dados. Coloque um proxy reverso com HTTPS na frente — Caddy, Nginx ou Cloudflare Tunnel — e só então ligue SECURE_COOKIES=true.

Caddyfile mínimo, com certificado automático 
agenda.suaempresa.com.br {
    reverse_proxy localhost:3000
}

Configuração

Variáveis de ambiente

Variável Para que serve Padrão
INVITE_CODE Código que os colegas digitam ao criar a conta. Deixe em branco só se a agenda estiver em rede interna. vazio
TURSO_DATABASE_URL Banco SQLite na nuvem. Quando preenchida, tem prioridade sobre o arquivo local. vazio
TURSO_AUTH_TOKEN Token de acesso do banco Turso. vazio
DATABASE_FILE Onde guardar o banco, quando ele é um arquivo local. ./data/agenda.sqlite
SECURE_COOKIES Ligue com true quando o site estiver publicado em HTTPS. false
SESSION_DAYS Quantos dias o login continua válido. 30
PORT Porta do servidor. Render e Fly definem sozinhos. 3000

Backup

Levar uma cópia embora

Tudo — eventos, comentários, histórico e pessoas — está em um único banco SQLite. Copiar esse banco é o backup completo.

Turso 
turso db shell agenda ".dump" > copia.sql
Arquivo local ou Docker 
docker compose exec agenda sh -c "sqlite3 /data/agenda.sqlite '.backup /data/copia.sqlite'"
docker compose cp agenda:/data/copia.sqlite ./copia.sqlite

Interface HTTP

Quinze rotas, todas em JSON

Tudo abaixo de /api — menos as rotas de autenticação — exige sessão ativa. As datas trafegam em ISO 8601 (UTC) e são exibidas no fuso do navegador de cada pessoa.

Filtrar
Método Rota O que faz
POST /api/auth/register Cria conta com name, email, password e invite.
POST /api/auth/login Entra na agenda e abre a sessão.
POST /api/auth/logout Encerra a sessão.
POST /api/auth/password Troca a senha da própria conta.
GET /api/auth/me Devolve o usuário da sessão atual.
GET /api/events?from=&to=&search= Lista os eventos de um período ou de uma busca.
POST /api/events Cria um evento.
GET /api/events/:id Evento completo, com comentários e histórico.
PUT /api/events/:id Edita o evento. Aberto a qualquer membro.
DELETE /api/events/:id Exclui o evento. Só o criador ou um administrador.
POST /api/events/:id/comments Comenta no evento.
PUT /api/comments/:id Edita o próprio comentário.
DELETE /api/comments/:id Exclui o comentário. Só o autor ou um administrador.
GET /api/users Lista a equipe.
PUT /api/users/:id/role Muda o perfil de alguém. Só administradores.

Segurança

O que já vem cuidado

  • Senhas guardadas com bcrypt; sessões em cookie httpOnly com SameSite=Lax.
  • Limite de 10 tentativas de login por IP a cada 15 minutos.
  • Todo conteúdo escrito pela equipe entra na tela como texto puro, sem HTML — o que fecha a porta para XSS.
  • As consultas ao banco usam sempre parâmetros preparados.
  • Em produção, sirva atrás de HTTPS e ligue SECURE_COOKIES=true.

Estrutura

Onde fica cada coisa

Sem framework de front-end e sem etapa de build: o servidor entrega os arquivos de public/ como estão. 

src/
  server.js          Express: middlewares, API e arquivos estáticos
  db.js              Banco (arquivo local ou Turso) + criação das tabelas
  auth.js            Sessões em cookie httpOnly
  wrap.js            Encaminha erros de rotas assíncronas ao tratador
  routes/
    auth.js          cadastro, login, logout, troca de senha
    events.js        eventos e criação de comentários
    comments.js      edição e exclusão de comentários
    users.js         equipe e permissões
public/
  index.html         Telas de login e da agenda
  css/styles.css     Estilo, com tema claro e escuro
  js/app.js          Calendário, formulários e comentários
scripts/seed.js      Dados de demonstração
